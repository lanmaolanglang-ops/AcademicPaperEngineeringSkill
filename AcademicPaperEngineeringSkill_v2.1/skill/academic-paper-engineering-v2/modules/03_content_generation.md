# 03 内容生成与章节校准

## Input

当前提纲、章职责、来源台账、原始记录、参数定义、篇幅契约与已有稿件。

## Process

1. 用最能检验论点的章校准分析深度和证据用法；若已有合格稿件直接沿用，不强制重写。章号与写作顺序由任务依赖决定。
2. 技术章节覆盖：背景问题 → 技术原理 → 工程现状 → 优势 → 限制条件 → 适用边界 → 小结。可合并成自然段，不必套七个小标题。
3. 段落按主张、证据、解释和边界展开。优势说明相对何种基准；现状写明日期与状态；限制指出何种工况会改变结论。
4. 每引入数字登记 DATA-ID 和所有位置；每引用观点登记 CLM-ID、SRC-ID 和精确证据位置。事实、预测、目标、模型、实测、假设及推导分开。
5. 计算先列输入、输出、边界、单位、公式和参数来源，再给结果与工程意义；结果不能超出输入证据。未提供的实验观测和调查样本不能代造。
6. 对已有稿件标明保留、删除、移动、重写和增加，记录原因与意义变化。重复机制放到最承担分析职责的一处，其他位置简要回指。
7. 图表使用稳定 ID，记录论证作用和源数据；概念图不伪装为实测因果，科学数据图用可复现的常规绘图方法。
8. 主体与结果稳定后回查引言、摘要及结论。摘要不新增未论证数据，结论回答原问题并保留限制。

## Output

可审稿件 REV-ID、主张—证据台账、数字出现记录、图表计划及待核项。修改动作写入 [决策模板](../templates/decision_record_template.md)。

## Validation

每节推进论点；每个判断能解释证据如何支持；没有仅列优点、新闻式夸张或参数堆积；重复内容已压缩但关键方法、工况和不确定性保留。

## Failure prevention

不为展示专业感规定每节必须放某数量数字；不以“推论”标签包容随意断言；不从一项性能推出整体成本、成熟度或规模化可行性。章内结构通过不代替后续审计。
