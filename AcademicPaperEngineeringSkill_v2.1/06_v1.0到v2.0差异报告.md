## 基线与保存结果

比较对象是实际存在的 v1.0 目录与本次独立 v2.0 Skill。v1.0 的 23 个 Markdown 文件以原交付清单作为基线，未改写、移动或删除；原 ZIP 保留。

本次旧版与新版均作为文件包交付，未修改全局技能安装。新版调用名为 `academic-paper-engineering-v2`，避免用户同时保存时无法区分版本。

## 修正原因

v1.0 按用户当时要求，只把有效方法和可泛化经验吸收入流程，未建立完整失败库。v2.0 的任务明确要求保存问题案例，因此新版本将失败原案存为诊断资料，仍禁止把它们当作操作步骤。

新增主记录表明：早期来源存在性核查与语言修正曾被过度当作完成证据；为了文后覆盖补错引、容忍首引顺序和未核参数的做法后来被修正。新版必须保留这种前后改变，避免把早期“通过”吸收为最终有效方法。

此外，材料读取显示分享快照可以成功取得，但不能消除附件、工具输出和检测复测缺口。新版不把“取得更完整记录”写成“所有证据均完整”。

## 相比 v1.0 的提升与实际限制

提升在于：不仅知道正确步骤，还知道哪些貌似合理的修改会制造错误、如何发现、以及修正后要验证什么。决策、问题和文件版本形成可追溯关系，源证据不足仍可被持续保留。

本版没有重新评价原论文，没有重新核验全部外部技术来源，也没有重做论文页面渲染、实体打印或检测。通用规则对四类主要文种进行静态适用性审阅；没有以真实新论文项目证明写作性能提升。实际成绩、检测率和录用结果不在验收结论内。
