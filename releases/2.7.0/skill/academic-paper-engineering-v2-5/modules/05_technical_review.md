# 05 专业技术审查

## Input

冻结稿 REV-ID、需求与论点、数据状态、术语定义、模型假设、原始技术证据和改动范围。

## Process

1. 采用 [academic_reviewer](../agents/academic_reviewer.md) 的只读视角，先检查影响成立性的错误，再做表达优化。
2. 基础概念：对象、量纲、名词、指标定义和分类是否正确；相近词是否实际代表不同量。
3. 物理边界：输入输出、系统层级、部件、接口、控制和系统行为是否形成正确作用链；有无漏计环节、重复计算或改变比较分母。
4. 工程条件：工况、规模、运行状态、辅助消耗、维护、资源和测量条件是否说明；设计能力与实际结果是否混淆。
5. 模型与参数：理想极限、条件模型、实验纪录、样机及量产/实际运行结果是否被误互用；参数范围能否适用于当前对象。
6. 因果与路线评价：关联是否被写成因果；是否由单指标推出最优、成熟或必要性；是否忽略反例和替代路径。
7. 逐章检查子问题、前提、证据解释、限制和结论回指。中心论点无据时明确影响并回到规划。
8. 输出分级问题，交主 Agent 决定、落实和复核；不因为用户要求保持观点就保留有据错误。

## Output

使用 [审核报告](../templates/review_report_template.md)，每个 ISSUE-ID 包含位置、问题、严重程度、原因、依据、建议、影响范围与关闭方法。

## Validation

Critical：主要结论或技术成立性存在致命问题；Major：局部结论、来源归属或提交硬要求被影响；Minor：不影响结论的表达与版式问题。证据不足的疑问明确标为待核，不能直接认定错误。重大项须实际修正或通过删去无据断言消除影响。

## Failure prevention

专业教师角色不代表真实外部专家认证；不引用历史审查评分证明技术成立；不能用语言流畅替代物理和数据检查。技术改动会影响数据、引用和结论，必须联动。

需要本阶段实际工具时，按需读取[执行细则](../references/method_review.md)；已有状态和职责保持。
