# Checking Contract：统一检查契约

## 目的与适用范围

统一检查记录和角色交接的输出格式，使每项结果可以追到实际对象、版本、范围和依据。适用于原有 data_auditor、citation_checker、academic_reviewer、document_formatter、final_acceptance；structure_optimizer 也使用同一通用格式记录其结构检查。

本契约不替代任何角色的 Process、专业规则或原报告；不新增 Agent。原角色继续产生数据表、支持关系、技术问题、页面记录或最终判定。本文件只定义这些产物共有的检查信息。

## 必需字段

可以使用共同报告头 + 逐项检查表，逐项以明确引用继承共同字段；不能让某条检查的不同范围、输入或限制被共同头掩盖。所有字段必须可定位；实际未知写“未知/未提供”，不造时间、工具、证据或来源。不适用字段注明理由。

| 字段 | 要记录的内容 | 约束 |
| --- | --- | --- |
| 检查ID | 当前项目中的稳定检查编号 | 可沿用已有编号；复查能找到前次检查，不用显示行号代替身份 |
| 对象ID | 被查稿件、主张、数字、来源、引用、图表、页面或交付对象；关联REQ-ID | 可引用CLM/DATA/SRC/CIT/FIG-TAB/ISSUE等原ID；不能制造不存在的对象 |
| 输入REV-ID | 实际冻结的输入版本 | 未建立版本先登记实际对象；Skill版本不是论文REV-ID |
| 文件身份 | 输入文件ID/路径、版本及SHA256或可靠标识 | 哈希只证明该文件身份，不能证明内容正确 |
| 检查范围 | 章节、出现位置、来源阅读范围、页/表或交付条件 | 不把抽样或片段检查写成全文检查 |
| 检查类型 | 结构、数据、公式、算术、参数、外推、技术、引用、格式、页面、最终验收等 | 由原角色负责；不能用一类通过替代另一类 |
| 执行方法 | 实际执行的读取、对照、复算、专业判断或页面查看 | 只写计划时不得称已执行 |
| 工具能力 | 实际可用工具/人工方法、确认依据和能力限制 | 可用不等于本项已执行；未知如实记录 |
| 实际证据 | 原记录、来源片段、计算结果、差异、页面或检查报告ID | 缺证据不记Passed；无来源不等于造假 |
| 定位信息 | 对象原句锚点、来源页/表/段、单元格、计算记录或页面位置 | 沿用原定位；无法取得位置明确写缺失，不补造页码 |
| 结果状态 | 通用检查执行/结果状态，以及该角色原有业务状态 | 两层分列，保持本文件的状态边界 |
| 限制条件 | 条件、假设、阅读缺口、工具范围、可沿用范围与禁止外推 | 不能用“已核”抹去条件和未核参数 |
| 未运行事项 | 尚未做的检查及原因、对本任务的影响 | 没有则写无；缺硬条件不能因标Not Run而视作满足 |
| 问题ID | 对应ISSUE-ID与原问题状态 | 无问题写无；未知不要假标无；关闭仍需复核 |
| 关闭标准 | 对应问题或检查条件如何满足、由哪个原角色复核 | 修订建议和写入不等于问题已关闭 |
| 时间信息 | 实际执行/复核/记录时间与时区；必要时区分来源发布和访问时间 | 历史时间未知保留未知；不由文件名或叙述猜造 |

## 逐项记录模板

| 检查ID | 对象ID/输入REV-ID/文件身份 | 范围/类型/方法/工具能力 | 实际证据/定位 | 通用结果状态 | 原角色业务状态 | 限制/未运行事项 | 问题ID/关闭标准 | 时间信息 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 待登记 | 待登记，或明确引用共用头 | 待定义；尚未执行 | 尚无 | Not Run | 待判，不能默认通过 | 待核实际缺口 | 待核问题；待定义关闭标准 | 未记录 |

共用头与逐项表合计覆盖上面的十六个字段。单一检查也可用键值列表，不要求新增文件或第二套专业台账。

## 状态边界

| 层次 | 保持的状态 | 解释 |
| --- | --- | --- |
| 通用检查 | Pending / In Progress / Passed / Failed / Not Run / Not Applicable | Passed表示指定对象、版本与范围的检查条件有实际证据满足；仅执行完、写完报告或字段齐全不等于Passed |
| 数据依据 | Verified / Partial Verified / Unsupported / Need Source | Data Auditor原四状态，只说明数字与参数的依据，不加入Unknown |
| 主张—证据关系 | Verified / Partial Verified / Unsupported / Need Source / Unknown | Evidence Ledger原五状态；未知、变化后待核不能当低风险 |
| 问题闭环 | Open / Resolved / Deferred | Resolved须有相应复核；Deferred不等于解决 |
| 论文/指定成果最终验收 | PASS / PARTIAL / BLOCKED / NOT RUN | 当前final_acceptance对指定对象的独立结论；不能由记录完整或机械检查自动产生 |
| Skill行为回归 | PASS / FAIL / PARTIAL / BLOCKED / NOT RUN | 本文件下方[行为评测状态契约](#行为评测状态契约唯一规范来源)为唯一规范；[发布检查](release_checks.md)引用它，不能映射成论文最终结论 |

尚未执行用 Not Run；已经执行但条件不满足用 Failed，并保留原业务状态与问题。Not Applicable 只用于真实不适用且有理由的项，不能为了通过临时排除硬要求。审计发现问题不妨碍如实交付审查报告，但不能据“报告完成”说论文已通过。

## 行为评测状态契约（唯一规范来源）

仅用于 Skill 维护的行为回归结果；每条记录仍绑定实际输入身份、范围、方法、原始产物与判据。使用既有“结果状态”栏或发布评测表，不新增业务状态。

| 行为结果 | 判定条件 |
| --- | --- |
| PASS | 实际执行，且该用例全部必需判据满足，有对应实际证据 |
| FAIL | 能够执行，但出现明确行为违例；保留触发输入、实际行为和未满足判据 |
| PARTIAL | 已经执行，但只有部分语义或证据满足；明确已满足与未满足范围 |
| BLOCKED | 因必要外部材料、工具或环境限制无法完成；记录阻断和已执行范围（如有） |
| NOT RUN | 没有实际开始执行；计划、读取规范或发现工具可用均不算执行该用例 |

外部限制不能转换为行为 FAIL；部分满足不能强制压成 PASS 或 FAIL。若同一用例既有已证实违例又有外部阻断，按独立判据分别记录并保留二者，不用阻断掩盖违例；汇总必须说明所覆盖范围。

历史三态 PASS / FAIL / NOT RUN 按原判据和原范围读取，原结果、原始字节与时间保持；不能据新契约补造过去未检查的条件。历史实际使用 PARTIAL / BLOCKED 的记录也按其原报告解释保留，不因旧三态枚举而拒读或改名。语义、范围或证据不足时注明兼容缺口，以新的当前检查记录补充并关联旧ID，不能回写历史结果或自动迁移为当前通过。

论文最终验收继续只用 PASS / PARTIAL / BLOCKED / NOT RUN，并按原 final_acceptance 与 SG01—16 归约；行为评测 FAIL 不是论文第五态。通用检查、数据依据四态、主张—证据关系五态、问题闭环三态保持原义，不能互相机械转换。测试行为正确拒绝正式提交时，可同时记录“行为 PASS；论文 BLOCKED”。

## 各角色仍负责的内容

| 原角色 | 专属输出和规则 | 通用契约的作用 |
| --- | --- | --- |
| [data_auditor](../agents/data_auditor.md) | 数字全部出现位置、四状态；公式/算术/参数/外推分判 | 绑定输入、方法与实际证据，不能因算术正确升级参数 |
| [citation_checker](../agents/citation_checker.md) | 来源真实性、实际已读、具体支持、编号和格式分别核 | 标明逐关系位置和覆盖范围，真实来源不自动支持所有主张 |
| [academic_reviewer](../agents/academic_reviewer.md) | 专业概念、工程条件、逻辑和结论边界，先只读报告 | 问题有原句、证据、严重程度与关闭标准 |
| [document_formatter](../agents/document_formatter.md) | 副本排版、同版DOCX/PDF、实际页面及恢复版本 | 保存/导出与实际页面核查分开，未查页面不记通过 |
| [final_acceptance](../agents/final_acceptance.md) | 只读读取有效检查，对指定最终REV作四态判断 | 核查输入绑定与范围，不代作者补数据、不代做专业审查 |
| [structure_optimizer](../agents/structure_optimizer.md) | 章职责、主线与逻辑关系，输出结构提案 | 结构通过只覆盖结构，不能代表全文可靠或已修改 |

## 交接、沿用与关闭

1. 原角色读取实际冻结对象，按其方法检查，再附共用信息；未做部分保持原真实状态。
2. 主Agent把报告ID与检查ID写入[项目运行索引](../templates/project_run_record.md)，继续维护唯一当前REV。共享头只减少重复录入，不增加第二套台账。
3. 接收角色先核对象、REV、文件身份和范围；输入不一致时按[修改管理](../modules/09_revision_management.md)确定受影响项，不复制旧Passed到新文件。
4. 旧检查有明确范围未变或差异复核证据时可以沿用：记录旧检查ID、旧输入身份、当前REV、沿用依据和限制。保留旧报告，不改写原历史字段。
5. 旧记录没有新契约字段时标明缺口；可依据当前实际检查补记，但不能追造原执行时间、源页或证据。关键缺口未解决时不称当前验收已具备。
6. 写入修订后由原职责角色按关闭标准复核，记录实际结果与未关闭ISSUE。final_acceptance仍只读判定，不能用验收动作修复稿件或自动关闭问题。

## 未知影响的处理

影响未评估时在严重程度栏说明“待评估”及需要核查的影响，不与Minor/低风险合写；这不是新增严重等级。未知不等于无问题，重要性未定的实质主张仍按Ledger交16字段。只有有据评估为非硬要求且不影响可靠性后，才归为低风险；正式必检未知按原控制器阻断。共用报告头引用多份输入时须明确各自REV和文件身份，不能统一替换成报告新编号。

## 禁止的推断

字段完整不等于论文正确；哈希一致不等于科学内容正确；计算正确不等于参数正确；文献存在不等于具体观点获支持；结构完整、排版完成、历史通过不自动等于当前PASS。

本契约没有评分、数据库、自动检索、自动验收或角色派发机制。它使已有检查可追踪，不扩张其可信范围。

## P2结果绑定

逐关系核查按[Ledger契约](../templates/evidence_ledger_template.md#p2逐关系执行契约e005-03)绑定目标子句与支持维度；完整主张通过不能传播为各边通过。正式验收按[Gate](../templates/final_acceptance_report.md#3-正式提交gate)区分阶段/正式对象；用户已请求时关键Not Run必须导致正式BLOCKED。旧CONDITIONAL PASS保留历史，不按新状态自动迁移。

## v2.5 分层交接与旧记录兼容

本文件的公共16检查字段与Ledger主张16字段是两套不同用途，不能相互充数。主张级CLM/汇总、关系级目标/方向/8维/强度/五态和出现位置级REV/文件/章节路径/锚点按[Ledger分层契约](../templates/evidence_ledger_template.md#v25-方向目标与逐次位置契约)交接。一个共用头不能补造缺失的某次章节、某边目标或未读范围。

新增“关系方向”是兼容文本列，也可明确标在既有范围栏；不是状态枚举。target_atomic_clause/核查目标、支持范围及既有别名继续可读，但Verified只相对于该行实际目标。支持、有限前提、反驳、背景、缺源和未查不能用同一标签混写；矛盾或反例的核查仍由原角色负责，不从关键词自动生成。

旧数据保持原字节/版本/原结果；缺方向、位置或原子目标时标兼容缺口，在新REV以实际读取补记并关联旧记录，不批量推断、不追造旧执行时间。不强制把全部旧Verified降级；只有完成当前范围有效性核查才能沿用。出现位置第2项可从旧字符串升级为列表或独立表索引，主张字段仍16个、关系维度仍8个；新调用者须接受列表/索引，不把字符串非空当覆盖完整。旧调用者只接受文本时可输出可读文本视图并另给每次位置表，不能丢信息。

交接记录分别注明位置覆盖检查、逐关系语义检查、参数/算术检查和聚合结论及其对象/范围。某种检查未执行保留Not Run；影响正式提交的关键证据/定位缺口交原角色，不用字段齐全或来源存在替代。

## 执行工具与副作用边界

开始执行前，在既有“工具能力/限制条件”字段记本次允许的读取、写入、网络范围。检查工具的实际副作用，包括TEMP脚本、解释器环境、缓存、Office/渲染临时目录与应用配置；需要落盘的辅助文件也须在授权范围内。能定向的临时目录仅对子进程设置，不改全局设置。不能满足约束时停止该步骤并记录原因，不借换工具、安装依赖或申请更宽权限自动绕过。

依赖不可用先做只读能力探查，优先现有获准工具；没有可用路径则如实记录Not Run/阻断影响，不自行pip安装、建venv或联网。用户明确授权安装或不同目录时按其真实范围执行，不把本规则变成所有任务的固定审批。

输出前逐列核状态枚举：数据仅四态，Ledger仅五态；Partial是支持强度，不是Partial Verified的状态简写；“不适用边”不是第六态，无关关系可不建立，已建立的行按实际目标判五态。Deferred只属于问题工作流。发现非法/矛盾状态时据实际证据重判，不能机械替换名称假称已验证。
