# Skill 发布检查

此文件是可重复使用的规范，不是当前或历史测试成绩。实际记录放在发布工程的独立报告中，不在论文核心流程加载。构建版本以SKILL.md的metadata.version为准，调用名academic-paper-engineering-v2-5；实际发布状态以对应版本的发布记录为准。

## A 静态与分发检查

- 核SKILL.md frontmatter：name、description及metadata.version；name与直接父目录一致。
- 保留九个modules、六个角色Markdown、七个templates、三个knowledge核心文件和原案例文件名。agents/openai.yaml仅UI元数据，不是第七个角色。新增reference须有入口且确有用途。
- 读取UTF-8，核非空、Markdown结构、相对路径和标题锚点；模板待填字段是输入接口，不声称已经完成。
- 官方quick_validate只检查格式/命名等有限范围，不证明行为正确、论文可靠或宿主已发现技能。
- 检查公开内容：无个人路径/凭据/原稿/对话/完整历史评测/内部判据；案例匿名且说明历史事实与教学假设的区别。
- ZIP实际重开：CRC、路径、重复项、清单、逐文件摘要；解压后重核入口/链接/资源。完整性不代表行为或论文通过。

## B 兼容与保护

修复只能在独立候选副本完成；原版本、原始论文、冻结输入/历史结果不改。记录旧新差异及前后保护范围和排除项。现有状态、公共检查字段、主张字段、关系维度、SG01—16和职责保持。

旧记录只在当前对象/范围有效且有复核依据时沿用，保留旧身份/状态/时间。新候选运行结果另存，不回填历史NOT RUN、FAIL或PARTIAL。

## C 按授权执行真实行为回归

发布维护任务明确授权时，可以在独立工作目录和独立执行上下文开展正常功能测试；本规范不启动模型、安装或自动派发角色。不要把旧版本一次性“禁止本阶段执行”的范围限制带到新授权任务。普通功能回归不等同OS隔离盲测，不宣称MXC或访问边界通过。

每项保存真实输入/版本/能力、完整响应、实际文件、工具/失败记录、原件前后身份和独立验收依据。只把输入和最少原始资料交给执行者，不把期望答案或历史失败结论当作提示。允许的测试/修复轮数以本次维护任务为准；保留每轮失败，不无限重试。

行为结果分层：PASS为已执行且对应全部判据有证；FAIL为可执行但行为违例；PARTIAL为已执行但只满足部分语义/证据；BLOCKED为必要工具/材料外部限制导致无法完成；NOT RUN为未开始。旧三状态框架的历史记录原义不重写。评测结果与论文最终PASS/PARTIAL/BLOCKED/NOT RUN分开。

优先覆盖：首轮需求与材料缺口、已有稿先诊断后授权副本修改、只读审查原稿保护、支持/反驳/背景方向、多次位置和修订映射、单边输入/过程/聚合、参数与算术、正式对象正负Gate、实际Word/PDF/目录页码/全页检查。正向对照不可全部降为Unsupported，背景边也不能冒充完整支持。

宿主安装/发现需要实际宿主证据；没有运行就是NOT RUN。手动读SKILL.md、复制到约定目录、官方格式校验或测试Agent按指定路径读技能，都不能单独称自动发现成功。

## 发布结论

按当前维护任务分别评估功能、格式/安装、隐私/许可和包完整性。关键未验证/未修复项阻断发布；有限非关键覆盖缺口披露限制。不得宣称所有模型/平台兼容、论文零错误或成绩保证。实际GitHub推送、创建仓库或Release仍需要用户明确授权。
