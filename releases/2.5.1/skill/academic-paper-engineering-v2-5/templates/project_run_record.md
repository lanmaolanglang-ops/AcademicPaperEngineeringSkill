# Project Run Record：论文项目运行索引

## 用途与边界

复制到实际论文项目，用于找到“当前正在做什么、使用哪个文件、哪些检查实际有效、下一步从哪里继续”。模板本身不是已执行的项目记录；待填、未知、未建立、未产生均不表示通过。

本文件只存简要状态、稳定 ID 和产物索引。完整 Evidence Ledger、数据表、问题/修改明细和决策依据保留在原报告中，用 ID 与位置引用，不在这里复制。小任务可将此索引合并进现有审核报告。

[修改管理](../modules/09_revision_management.md)仍负责唯一当前版本、决定和影响复核；本索引不成为新的模块或 Agent。检查结果按[统一检查契约](../references/checking_contract.md)登记，角色职责和原状态定义保持。

## 使用规则

1. 开始或恢复任务时先核实际文件和可读范围，再填索引。历史消息、旧报告和文件名不能代替当前读取。
2. 区分 Skill 版本与论文 REV-ID。所用Skill版本按实际读取的入口metadata.version登记；论文尚无稿件时，当前 REV-ID 写“未建立”，不能把“2.2”当论文版本或凭空声称已有候选。
3. 原稿、当前候选、最终交付和恢复文件分别登记。文件身份使用实际路径/文件 ID 与可靠版本标识；能取得时记录 SHA256。不能取得可靠身份时写明限制，不能称已完成身份核对。
4. 文件名“最终版”不能证明最终状态。最终版本字段只有在相应交付范围的验收报告绑定该 REV-ID、文件身份和实际检查状态后才填写；否则登记为候选或未产生。PARTIAL保留残留问题索引，不假标Resolved；历史CONDITIONAL PASS不自动转换为正式提交PASS。
5. 原始材料、派生笔记和历史报告区分登记。已读取要注明实际范围；未读取要写原因和阻碍。下载、文件存在或只读到摘要均不等于全文已读。
6. 工具“可用”与检查“已执行”分开。可用能力不能让尚未执行的检查变为 Passed；能力未知或不可用不允许取消提交硬要求。继续可以独立完成的工作。
7. 问题状态和决定落实状态从原记录引用；只有相应复核支持关闭才能记录 Resolved。新建议、已决定、已写入和已复核分别注明，不由本索引代做决定或关闭问题。
8. 按已有授权推进，只有影响目标、硬要求或必须由用户提供的原始材料才请求必要信息。记录原授权和未决缺口，不把索引更新变成固定审批。
9. 中断前保存当前文件身份、检查索引、未完成事项和下一步；恢复依据是文件身份 + REV-ID + 实际检查状态。任何一项不一致先核差异，沿原修改管理规则处理受影响范围。

## F. 下一步与中断恢复

| 字段 | 记录 |
| --- | --- |
| 下一步行动 | 待填：具体对象、操作、范围与现有授权 |
| 必需补充的信息 | 待核；无则明确写无 |
| 最后实际完成点 | 未记录；写文件身份和已执行检查ID |
| 中断时保存的文件/恢复位置 | 待登记；无保存结果则说明 |
| 恢复前必须确认的事项 | 文件身份、REV-ID、有效检查和未完成范围 |
| 恢复后的基线/差异记录 | 未执行；发生差异时链接原修改记录 |

恢复顺序：读取索引 → 核当前文件身份与 REV-ID → 对照已执行检查及其范围 → 核未完成事项与已有授权 → 继续下一步。旧检查有范围未变或差异复核证据才沿用；不存在的时间、文件或检查不补填为已完成。

## 索引自检

- 每个状态能定位原文件或报告，不凭索引单独升级证据状态。
- 当前 REV-ID 与实际候选一致；最终文件有对应范围的实际验收。
- 已读/未读、可用/已执行、提案/写入/复核保持区分。
- 完整证据、数据、问题和决定明细仍只有原记录，不维护重复副本。

## P2正式目标索引

增加索引：用户原始目标；是否请求正式提交；阶段对象/REV/检查报告/状态；正式DOCX/PDF及其他必需对象身份（缺失也登记）；正式Gate报告路径/状态；阻断ISSUE与下一步。只引用明细，不复制台账。不得因为阶段PASS或文件名最终版而自动将正式目标记完成。

## v2.5 证据修复恢复点

在既有台账/检查索引中引用当前CLM的逐次位置覆盖记录、逐边目标/方向复核及受影响DEC/REV，不抄整套位置或关系。恢复核实际当前稿锚点、未解决冲突和旧→新映射；规则见[Ledger契约](evidence_ledger_template.md#v25-方向目标与逐次位置契约)。文件名、原聚合Verified或历史删句都不能证明这些检查已经完成。
