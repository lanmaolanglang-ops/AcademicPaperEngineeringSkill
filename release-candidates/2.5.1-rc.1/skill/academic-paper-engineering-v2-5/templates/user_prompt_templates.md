# User Prompt Templates：用户调用模板

选择一个模板，填写方括号字段，删除不适用选项后直接发送。资料可分批提供，不需要自行填写完整内部台账。调用名称为 `$academic-paper-engineering-v2-5`；已安装 v2.0 的原调用名仍由原版本提供，本文件不注册自动别名或安装技能。

## 模板1：从零开始写课程论文

请使用 Academic Paper Engineering Skill 2.5.1-rc.1，协助我完成课程论文。

- 题目或暂定方向：[填写题目/方向]
- 学科及目标读者：[填写学科及课程层次]
- 字数与统计范围：[填写要求；不明确时先说明采用的口径]
- 格式要求：[提供模板、引用规则及指定版本；未知项标未知]
- 已有材料：[逐项列出实际文件或粘贴正文；没有则写无]
- 截止时间与时区：[填写日期时间及当地时区]
- 最终交付：[填写 DOCX、PDF、图表或其他需要的文件]

先读取材料并报告可读范围及缺口，明确研究对象、问题和边界。按需求分析 → 结构设计 → 内容生成 → 数据审计 → 技术审查 → 引用审查 → 文本质量控制 → 排版交付推进，修改管理贯穿全过程。

请用 Evidence Ledger 追踪关键主张、数字、推论与来源；原始记录不足时不要生成实验或统计结果，预测和假设保持身份。给出的要求已足够时继续执行，只有影响研究目标或必须由我提供的原始材料才提出具体问题。

最终由 Final Acceptance Controller 判断当前正式对象，输出 PASS / PARTIAL / BLOCKED / NOT RUN，并说明依据与未完成项。

## 模板2：已有论文深度优化

请使用 Academic Paper Engineering Skill 2.5.1-rc.1，对我的已有论文进行深度优化。

- 当前稿件：[提供 Word 文件或完整正文]
- 用途、学科与质量目标：[填写]
- 必须保留的结构及内容：[填写；事实错误须指出]
- 允许调整的范围：[填写结构、内容、字数、图表与引用范围]
- 可用材料与来源范围：[填写]
- 篇幅、格式及截止时间：[填写]
- 本次修改授权：[默认先完成诊断，再在上述范围内落实有证据的修正；若只需审查请明确写只读]

先完整读取实际可用稿件，登记版本与缺口。禁止在诊断报告输出前直接改文件，先分别输出结构问题、技术问题、数据问题、引用问题，写明位置、依据、严重程度和建议；缺失证据标待核。

诊断报告输出后，按本次已给的修改范围和授权执行定向修改，不重复索取相同授权。改变研究目标、涉及新实测结果或超出范围时先提出所需信息，不代填。

保留原稿并创建新版本；建立或更新 Evidence Ledger 和决策记录，联动摘要、正文、图表及引文。实际修改后复核，再用 Final Acceptance Controller 输出本次交付判定。只读模式仅交付审查报告，不宣称整篇已修正完成。

## 模板3：论文提交前审查

请使用 Academic Paper Engineering Skill 2.5.1-rc.1，以指导老师视角对当前论文进行提交前只读审查。

- 稿件、版本及文件：[填写/提供]
- 提交要求及学科：[填写]
- 已有来源、审计和修改记录：[提供；缺少则明确标记]
- 本次审查范围及截止时间：[填写]

检查学术逻辑、技术准确性、数据来源、引用匹配与编号、格式和页面。输出审核报告，按问题位置、严重程度、原因、证据、修改建议及关闭标准整理；说明已查范围与未查范围，不编辑正文、不补造来源。

Evidence Ledger 用于定位主张依据；Data Auditor 的参数状态独立保留。不能因为语言流畅、结构完整或文献存在就认定全部可靠。

本次输出是审查报告及风险结论；请求能否正式提交时必须运行 Final Acceptance Controller，材料不足明确BLOCKED。只要求阶段审查时正式Gate记NOT RUN。不能把审查结束说成修改已完成，也不预测教师成绩或检测分数。

## 模板4：生成最终 Word/PDF

请使用 Academic Paper Engineering Skill 2.5.1-rc.1，将当前内容候选整合为最终 Word 和 PDF。

- 当前候选稿与 REV-ID：[提供；未知则先登记实际版本]
- 数据、技术、引用审查及修改记录：[提供/注明缺失]
- 版式模板、页码及目录要求：[填写/提供]
- 图表源文件和对应数据/来源：[提供/注明缺失]
- 必要封面元数据：[仅提供本项目需填写的内容]
- 字数口径、目标应用及截止时间：[填写]
- 最终交付清单：[填写 DOCX、PDF、源图、恢复版本和验收报告]

先核对当前稿件及审查范围，保留原稿，在新版本中整合已落实内容。禁止覆盖唯一底稿；未授权的技术变更交回相关角色处理。

插图独立管理源文件、图表 ID、数据来源和正式题注，插入后再核尺寸、清晰度与位置。更新标题层级、目录、图表编号和页码；导出后检查 DOCX/PDF 内容一致及实际分页，保留可恢复的上游版本。

最后由 Final Acceptance Controller 输出验收报告，绑定最终文件、REV-ID、范围和证据。缺少必要审计或页面检查时标明阻碍，不仅凭成功保存或导出给出 PASS。

## P2调用约束

上面模板涉及“能否提交、准备最终提交、生成最终Word/PDF”时，必须执行[正式提交Gate](final_acceptance_report.md#3-正式提交gate)，即使材料不齐。若文字含“材料齐备时再验收”，仅指补全检查以求PASS，不能省略当前BLOCKED判定。输出阶段对象和正式对象的独立结论；正式状态PASS / PARTIAL / BLOCKED / NOT RUN按控制器，不把历史CONDITIONAL PASS作为本版正式放行。
