# Evidence Ledger：证据台账模板与执行规则

## Purpose and scope

管理“主张为何存在、证据支持到哪一步”。复用 v2.0 的 CLM-ID、SRC-ID、DATA-ID、CIT-ID 和 REV-ID；仅增加 EVID-ID 标识具体证据片段或计算记录。不要求建立数据库，小任务可将以下表合并到已有审核报告，但保留对应关系。

Data Auditor 核数字、参数和计算；Evidence Ledger 管主张—证据关系。台账不能替代数据审计、技术审查或引用核查，也不能因为填满表格就把主张判为 Verified。

## Input

当前 REV-ID、正文及图表、主张与来源台账、数据审计结果、技术与引用报告、计算文件和修改记录。

## Process

1. 逐项登记需要支撑的事实、预测、假设、计算、推论和建议。内部编号不作外部事实审计；同一句有不同类型或不同支持范围时拆分 CLM-ID。
2. 为来源的具体页、表、段、数据字段、原始观测或计算记录分配 EVID-ID。记录实际阅读范围及证据版本，不凭空补页码或声称读过不可访问内容。
3. 按“CLM-ID—EVID-ID—SRC-ID”逐条建立关系。一个主张可有多条关系，一个来源可支持多个主张，但每条关系均需独立判断；源的真实性或领域相关性不自动传播为所有主张的支持。
4. 引入数字时关联 DATA-ID，并填写数值、单位、时期、对象、统计口径和来源位置。读取 Data Auditor 的四状态与独立计算结果，不用台账的状态覆盖它们。
5. 推论和建议记录前提、计算或中间判断、推导步骤、反例、适用条件与结论边界。计算记录公式、输入、单位、复算和参数身份；正确计算只能验证相应条件下的关系。
6. 聚合当前主张的证据链。只有覆盖了当前表述的必要内容，且冲突、适用条件和相关审核已有明确结果，才判定其状态。只验证某一子句时拆分或收窄原主张，不用部分支持包装完整断言。
7. 正文、数据或来源改变时沿 CLM/EVID/SRC/DATA 关系标出受影响项，交原角色复核；尚未重判的台账项设 Unknown。保留旧 REV 的记录，不改写历史审计结果。

## 主张类型

| Claim Type | 登记内容 | 不得默认推得 |
| --- | --- | --- |
| Fact | 事实断言及对象、时期和条件 | 来源提到相关主题就等于事实已证实 |
| Prediction | 预测机构、发布时点、预测期、情景和对象 | 预测已核实就变为已实现事实 |
| Assumption | 作者明确设定、设定理由、用途和限制 | 作为设定可用就等于现实参数正确 |
| Calculation | 公式、输入、参数身份、复算及输出边界 | 算术正确就证明参数或经济性正确 |
| Inference | 前提 CLM-ID、中间关系、推导链、反例和边界 | 有几条真实前提就一定支持该结论 |
| Recommendation | 判断依据、目标、权衡、适用条件和限制 | 建议有理由就证明它普遍最优 |

这六类是主张层分类，不替换 v2.0 的数据性质字段。原 Forecast 可对应 Prediction；数字推导通常对应 Calculation，非数字推导对应 Inference；实测或引用模型结果可登记 Fact 并保留原 Measurement/Model 标签；目标声明按实际句意登记 Fact 或 Recommendation，保留 Target 标签。不能仅按标签自动转换主张含义。

## 状态与Validation

状态指“当前 REV 中该性质主张与证据的关系”，不是整篇论文验收结论：

| 当前状态 | 条件 | 处置 |
| --- | --- | --- |
| Verified | 当前句意的必要支持已覆盖，适用条件明确，相关审核记录有效且支持当前性质的表述 | 仅在已核性质和范围内使用 |
| Partial Verified | 已支持部分，但必要字段、条件、阅读范围或推导环节不完整 | 补证、拆分或收窄后重判 |
| Unsupported | 已检查依据不支持当前断言，存在未消除冲突或推导不能成立 | 更正、删除或取得对应证据后重判 |
| Need Source | 已确定需要证据，但来源、原始记录或必要前提尚缺失/不可读 | 查源或按允许范围保留待核，不作事实背书 |
| Unknown | 尚未判断、输入不清或变更后待重判 | 分派原角色核查，不能解释为低风险或通过 |

Verified 的假设仅说明该设定及用途被清楚记录，不证明现实真实性；Verified 的条件计算仅说明推导在所列前提下成立。关联参数仍可为 Need Source，必须保留其身份和外推限制。事实性结论若依赖这些未核参数，不得据条件计算的 Verified 升级。

## Output and handoff

输出上述表或合并台账、关键主张覆盖清单、冲突与待核项、所用报告 ID 和输入 REV-ID。

- data_auditor 返回数字与参数结果，台账引用 DATA-ID。
- citation_checker 核来源真实性、证据位置和主张匹配，台账记录 SRC/EVID/CIT 关系。
- academic_reviewer 核前提、推导、工程边界和结论范围。
- document_formatter 变更位置时更新锚点并保留内容身份；内容改变交回相关角色。
- revision_management 维护 REV/DEC/ISSUE 和变更传播，最终验收控制器读取台账，不用它替代原检查。

核查失败或缺失时保留真实状态；每个声称已通过的检查都关联对象、版本、范围和证据。

## P2逐关系执行契约（E005-03）

这是上述A–D的必执行规则，不增加台账或新的状态系统。重要主张输出之前须完成下列顺序；字段可合并展示，但必须由执行者提供定位，不能依赖评估者事后补全。

1. **先原子化。** 同句的数值、年份、统计对象、趋势及因果结论可分别真伪时，拆分CLM并保留原句/章节/全部复用位置；不强行给整句同一个Verified。拆分不能把错误“对象+年+数值”拆到失去原组合含义，仍要保留原组合的判定。
2. **后逐边。** 表B每行只处理一个CLM—EVID—SRC关系，指定核查的原子子句或前提。来源存在：已定位/未定位/未知；实际阅读：指定页段已读/仅元数据或摘要/不可读/未读。两项分别记录在已有“来源状态及引用核查记录”和“实际阅读范围”字段。仅取得文件、书目或引用编号不算已读对应证据。
3. **再对照。** 对值、单位、时间、统计对象、地理范围、口径/情景、事实或预测性质、结论分别标明“支持/部分支持/不支持/冲突/未核/不适用”，逐维是说明标签，不替代Ledger五状态。写出来源实际支持的完整边界，以及原句超出的具体部分。来源只能提供背景时不能把该行写成对完整主张Verified。
4. **判边后聚合。** 每行先给支持强度、关系五状态和判断依据，再汇总CLM；严禁将CLM汇总状态复制到全部关系或据其批量生成Passed。Contextual只表示背景相关：对于完整断言须记Partial Verified（确有部分支持）、Unsupported（已读不支持/冲突）、Need Source（必要证据缺失）或Unknown（尚未判断），不能单凭相关记Verified。若实际直接覆盖某个子前提，拆成该前提并重新判Direct/Conditional，不把原背景行反向改成完整支持。完整Inference可经表D和全部必要前提验证，不要求每条背景文献直接证明整个推论。
5. **缺口先处置。** 优先拆分、缩小范围、改为有依据的条件表述，或登记待核/取源；不可为编号闭环强挂引文。加“预计/约”不能修复年份和对象错配。Unsupported表示当前依据不能支持，不自动等于数字伪造；Need Source表示未核，不得统称“已证明错误”。
6. **输出前自查。** 每行Verified必须能从实际已读证据重建该行核查目标；Partial不得简写“支持”省掉缺口。通用结果Passed若表示“完成了审计并发现不支持”，必须明确其对象是审计动作，另列关系Unsupported；不得使Passed看起来是该主张已获背书。未做判定保持Not Run/Unknown。

支持强度和关系状态不互相替代：Direct只有在当前目标必要维度覆盖且相关复核有效时才Verified；Conditional的Verified仅限明列前提，现实参数仍独立；Partial不能变完整Verified；Contextual/None/Contradictory不能直接给予完整目标Verified。源真实、已读取、支持当前主张三个结果不可互相替代。

## v2.5 方向、目标与逐次位置契约

下列规则精化已有A—D及P2步骤，不增加主张16字段、关系8维或五态。方向是证据与**本行目标命题**之间的语义描述，不是第六种关系状态。新增输出可在表B追加“关系方向”列/键，或在原“支持的具体部分/适用条件”中明确标记；两种写法等价。旧字段/别名继续有效，不能仅凭别名推定语义满足。

### 1. 层级与核查目标

| 层级 | 复用位置 | 本层记录什么 | 不允许的替代 |
| --- | --- | --- | --- |
| 主张 | A与重要主张16字段视图 | CLM-ID、当前REV的命题/性质、重要性、汇总状态及D链 | 完整CLM文本不能自动充作每边核查命题 |
| 出现位置 | A正文位置及16字段中的第2/3项 | 同CLM在当前文件/REV的每次出现、章节路径、锚点和原文 | 单个段落号或让读者全文搜索补齐所有位置 |
| 证据关系 | B；16字段第11—15项可索引B/D | 一条CLM—EVID—SRC对**明确的原子子句或前提**的方向、强度、五态、阅读与范围 | CLM汇总状态或引用编号不能替代本行判定 |
| 关系8维 | B逐维支持 | 值、单位、时间、统计对象、地理、口径/情景、事实/预测/假设性质、结论，相对于本行目标判断 | 对整篇论文或其它边的正确性打包赋值 |
| 数据/推导 | C与D | DATA、输入/参数身份，公式/过程/结果及必要前提和专业复核 | 算术正确不覆盖参数或实证真实性 |

表B的“关系核查目标（原子子句/前提）”是判定对象；`target_atomic_clause`、核查目标等既有键可作其别名，但内容须是本行实际命题。CLM-ID只表示归属。若目标含多个可独立成立的子命题，先拆主张或拆关系目标；不能把范围栏当作已过标目标的免责脚注。

### 2. 方向、强度与五态的执行判定

先实际读取并确认本行目标与证据的对象/时期/谓词是否相同，再记录关系方向及其适用范围。方向用可解释的文字，如“支持该输入”“反驳该普遍断言在所列工况下的成立”“仅背景”“未建立支持/反驳”。不增加受控状态枚举；五态、六种支持强度及数据四态保持原义。

| 实际关系 | 方向和强度用法 | 关系状态及必要理由 |
| --- | --- | --- |
| 已读证据完整支持本行事实/结果 | 方向写支持本行目标；Direct | 必要维度覆盖且复核有效才Verified；不推给其它目标 |
| 在明列假设下完整覆盖目标 | 支持所列条件下的目标；Conditional | 可Verified，但参数现实状态独立，必须关联条件和D链 |
| 仅支持复合命题中的真实一部分 | 支持哪一部分明写；Partial | 保留整个目标时Partial Verified并列未覆盖部分；优先改为该部分的原子目标后独立重判，不能自动升级 |
| 只支持计算输入或某个前提 | 方向写“支持输入/前提X”；目标直接写X | 若X确被完整覆盖，X的这条边可Direct/Conditional及Verified；不能仍以完整计算结论为本边目标再说只支持X |
| 对目标形成可核反例或直接冲突 | 明写反驳哪一断言、适用条件；Contradictory | 原目标关系Unsupported；这不是Partial支持。证明存在反例不证明相反的普遍命题 |
| 只与主题背景相关 | 明写背景及不能支撑部分；Contextual | 有真实部分支持用Partial Verified；已读不支持目标用Unsupported；缺必要证据用Need Source；尚未判断用Unknown，不能一律降成同一种状态 |
| 已读取但未能支持目标 | 明写未建立支持，不能冒称反驳；None或实际相关的Contextual | Unsupported表示这份依据不足/不支持，不自动证明命题虚假 |
| 必要依据缺失/不可读 | 方向尚不能确认，记录缺失/实际可读层级；未判强度或None并解释 | Need Source；已知缺源与尚未开始评判的Unknown区分 |
| 尚未检查或变更后待重判 | 方向未判，不填写已读支持；强度待判 | Unknown，通用执行状态Not Run或实际执行进度；不能当通过 |

**反例须核同一命题。** 证据只谈成本或设备选型，不能未经核查就宣称已证明效率变化；仅有“存在影响因素”的相关说明也不等于已取得具体数值反例。若只能否定原引用的支持充分性，就这样记录；不要为了纠正Partial标签而制造Contradictory。有限反驳不能被写成对原断言的有限支持。原断言删除后，旧反驳/不支持行保留历史身份，新句须另核。

同一主张有支持和反驳来源时，逐边保留各自方向/范围；不能投票或平均强度。Direct/Verified只覆盖该边已证命题，汇总必须记录冲突及其能否用对象、时期或条件解释。未解决的实质冲突不把整体判Verified；依据确实冲突时整体Unsupported，部分缺口用Partial Verified，缺必要证据用Need Source，尚未评判用Unknown。不能为避错把全部边标Partial或Unsupported。

### 3. 每次出现的显式位置记录

仍在A/16字段第2项中放位置列表或指向既有位置表，不新建全局ID体系。最小出现键可由 **CLM-ID + REV-ID + 文件身份 + 位置标识 + 片段区间/出现序号** 组成。每条实际记录提供：

- 当前REV及文件身份；段落/单元格/行等稳定位置标识。
- 章节路径（如摘要、章/节层级、结论）；资料无显式标题则说明实际观察“无显式分章”，不能自创章名；确实不能确认则标未知/未核并说明原因。
- 该次原句或可唯一回查的原文锚点；同段重复时加片段区间或出现序号，不能只给同一个P号。
- 该次位置是否实际核对及限制；来源页段属于B，不拿它代替正文位置。

覆盖检查必须把全文实际出现集合与位置记录逐次对照，至少含摘要、正文、表注/题注及结论中的复用。没有直接给位置表的逐字段索引不能记覆盖检查Passed；章节真实未知如实保留，不能凭字段非空充作已定位。缺位置不自动等于该科学命题Unsupported，应单列定位检查缺口及对使用/交付的影响。

移段/改章/排版转换后，用实际新文件重建位置；保留旧REV位置和旧→新映射/DEC，不能仅换REV标签。只提议移动尚未写入时，不创建已生效的新锚点。CLM-ID在同一命题复用和纯移位时保持；限定改写可在同ID的新版快照中明列语义差异/受影响关系，不能把旧Verified带过来。若对象、谓词或结论已是另一独立命题，用原CLM机制建新ID并记录替代/拆分关系，旧ID/旧记录保留。

### 4. 输入、过程、结果及聚合分别可追溯

在已有C/D中列出每个必要输入/前提的CLM/DATA、状态、SRC/EVID及范围；明示额外作者假设/定义。计算或推导记录公式、单位/基准、实际复算、结果目标、遗漏环节及反例/限制。输入真实有据、算术正确、结果性质和完整结论分别复核。

若源只给两个年末存量，本源行的目标是相应存量输入；差分/换算结果由实际计算记录在同版同对象条件下支持，不让源单行直接验证推导值。若源直接报告所需同口径结果，该结果行可以Direct/Verified，不必强迫把所有结果都作假设。旧作者设定只支持其原本写出的设定；后加共同基准等条件须在当前设定记录/复核中定位，不能回写成旧稿已有。

完整Inference可以经D链和全部必要前提在限定范围Verified，虽有其它背景边Partial；背景边仍不升级。反过来，一个输入边Verified不证明全部输入、过程或最终结论已核。只有前提、过程及冲突处理足够才汇总；不得用整体正确把单边过标合理化。

### 5. 输出前一致性与变更交接

按本行实际目标逐条核：目标是否原子且明确；已读片段能否重建该目标；8维和方向/强度/五态/范围是否一致；“只支持前提、不支持结果”等说明是否与标记冲突。若目标写完整结论但范围只到前提，**不能保留该行Verified**：改为真实前提目标并重判，或在原目标下保留实际部分/不支持/缺源状态。不能靠另一个计算边或CLM聚合补救本行。

位置覆盖、关系语义和通用审计执行结果分开：完成一次检查且发现不支持，可以交付检查报告；Passed必须说明满足的是何项审计动作/条件，原目标仍Unsupported。若本行要检验“主张已获充分支持”，发现不足则该检查Failed，不能据“审计已做完”写Passed。

主张删去/限定/换源或位置变化后，沿原修改管理复核所有受影响出现、关系、数据和摘要/结论；历史行不重写，新REV未判项Unknown。交原引用角色核方向和源匹配、原数据角色核输入/参数、原技术角色核D链；最终控制器只读接收有效结果，定位/语义关键缺口未闭合时不得正式放行。

## 交付前的字段与关闭核对

- 重要CLM逐条给上面的16字段→实际A/B/C/D或位置索引；通用检查头的16字段不能充数。缺项明确列出，不因多份报告存在宣称已完成该契约。
- 同一关系行只给一个实际目标、一个对应强度和一个五态；“前提Direct/结论None”须拆为可分辨的目标关系，不能挤在一行以脚注免责。无关边可不建立，已列边不创造“不适用边”状态。Partial强度不作关系状态简写。
- 未读原文时分别写来源存在性及阅读范围，支持未核：Need Source或实际尚未判断的Unknown；不能说“原文已证不支持”。撤回无据断言只说明当前缺证，不证明来源不存在/伪造或全文不支持。
- 反例相关ISSUE的关闭标准必须明确处理现有反证的适用条件与有效性，或有据收窄/撤回原断言；新增正向来源、删句或引文数量增加本身不消除既有反例。来源定位须实际回查数值行/段，不拿标题行替代证据行。
