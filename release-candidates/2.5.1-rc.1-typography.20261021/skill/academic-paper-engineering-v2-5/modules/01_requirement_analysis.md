# 01 需求分析与材料读取

## Input

题目、读者、课程或报告要求、资料、原始记录、已有稿件、格式模板、输出形式、期限及允许修改范围。

## Process

1. 先逐项登记材料是否存在、能打开、读到正文、是否被截断及附件是否另需读取。长段落或表格预览受限时用可用原生解析补读；不能把标题或摘要当全文。
2. 区分原件、版本稿、用户转贴、历史审查、候选方案及缺失记录。标记来源和时间顺序，删除消息或被隐藏的输出为 `[NOT_AVAILABLE]`。
3. 明确成果目标和入口阶段：规划、章节、审查、整合、排版或完整交付。不要因选用某个工具而改变任务成果。
4. 将要求拆为可验收项目，分别登记内容范围、来源范围、改动范围、篇幅统计口径和文件要求。材料可用范围改变时记录依据。
5. 字数写清汉字、字符或指定软件计数，及摘要、表格、标题、目录、参考文献是否纳入。计划字数不能当实测字数。
6. 引用规范记录所选 GB/T 7714 版本、顺序编码或其他制度及机构模板；按有效提交要求执行，不自动沿用旧项目版本。
7. 隐含目标标为解释或假设，列出依据；评分标准缺失就说明，不预测真实成绩。小偏好可以合理选择，重大边界缺口需要用户具体信息。

中文论文另记录版式依据：用户/机构模板优先；没有具体模板要求时采用[CN-PAPER-DEFAULT-1](../references/chinese_paper_format.md)，明示可覆盖的产品默认。字体偏好缺失可据此继续；外部硬要求未知不能虚构为已确认。只读任务先诊断，不自动改排。

## Output

材料读取报告及需求表：`REQ-ID | 要求 | 出处 | 硬约束/偏好 | 验收方法 | 当前状态`。另列不可读材料、当前基线 REV-ID 与可独立推进的阶段。

## Validation

每项硬要求可检查；原件、转贴和报告证据已区分；未知没有被填成事实；个人字段不会流入 Skill 或公共案例。输入足以推进哪些阶段写清，不笼统声称“材料完整”。

## Failure prevention

分享快照可完整提取但附件和隐藏输出仍可能缺失。链接读取失败先记录事实并使用已提供材料，不寻求超出授权的账户历史。需要实验结果时不能把通用假设写入真实结果栏。
