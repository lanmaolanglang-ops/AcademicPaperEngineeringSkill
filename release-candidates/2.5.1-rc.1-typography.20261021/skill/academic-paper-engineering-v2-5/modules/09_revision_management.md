# 09 修改管理、恢复与最终接受

## Input

实际材料、需求契约、冻结稿 REV-ID、问题清单、用户授权、候选文件及检查记录。

## Process

1. 开始时登记当前基线、文件清单、上游版本、实际可读范围及可靠版本标识。文件名含“最终”也必须检查，不依旧记忆覆盖。
2. 以 REQ、CLM、SRC、DATA、CIT、FIG/TAB、ISSUE、DEC 和 REV 稳定 ID 关联需求、证据、数字、引用、图表、问题、决定及文件。
3. 使用 [决策记录](../templates/decision_record_template.md) 记录原案、问题、发现方式、依据、备选处置、最终决定、实际修改、结果及通用规则。提案与已写入分开；旧决定被替代时保留关系和原因。
4. 审查角色针对冻结版本提交报告，主 Agent 统一裁决和整合。独立并行审查仅在实际授权且工具可用时使用；同一 Agent 可按角色分阶段完成。
5. 在既有授权范围内直接落实必要修正；调整任务目标、必须新做实验或需要用户实测资料时才提出具体问题。历史逐轮确认不是统一审批要求。
6. 按影响复检：新数据重查主张、引用及所有复用位置；移动章节重查首引、图表和目录；改中心论点回到规划并查全文；纯版式变更重查页面及内容差异。
7. 中断时记录已完成与未完成文件，不假报成功；有限尝试后保留可恢复状态。恢复先核基线、完成点、临时输出和已有授权，再继续，不重做已验证工作。
8. 在最终文件上完成验收，绑定哈希/版本。收集失败模式时区分已发生、仅报告、预防风险、已修正和未闭环；发布知识前匿名化。

## Output

版本链、问题与决策库、修改对照、复核记录、最终文件清单、缺口及恢复位置。

## Validation

| 对象 | 状态规则 |
| --- | --- |
| 检查执行 | Pending / In Progress / Passed / Failed / Not Run / Not Applicable；不适用说明理由 |
| 数据依据 | 采用模块 04 的四状态，不与检查执行状态混用 |
| 问题闭环 | Open / Resolved / Deferred；Deferred 说明影响，不自动算解决 |
| 材料缺口 | [NOT_AVAILABLE]，说明无法支持的判断 |

需求硬约束满足、Critical/Major影响消除、未核项不支撑事实结论且文件一致，是必要条件；正式结论仍由[控制器](../agents/final_acceptance.md#输出前的状态归约)根据当前对象判定。未关闭Minor/Deferred不能从最终问题清单中消失：仅低风险残留为PARTIAL，有关键缺口为BLOCKED，零未关闭提交问题且条件全核才可PASS。假设分析被任务允许时可保留，但不能替代要求的真实结果。

## Failure prevention

不得把发现、修改建议、写入完成、预检通过和最终验收合为一个“已完成”。备份证明保护措施，不证明发生了覆盖事故；哈希证明文件身份，不证明科学结论正确。

## v2.5 证据与位置变更复核

按[Ledger契约](../templates/evidence_ledger_template.md#v25-方向目标与逐次位置契约)在已有DEC/REV中保留CLM旧句意、旧关系和每次位置，新稿列实际新增/限定/删除及旧→新锚点映射。仅位移保留CLM身份；实质新命题按原机制新建/关联替代，不能复用旧支持结果。所有受影响关系先按当前目标重判，未判Unknown；仅删句不自动关闭关系标注问题。运行索引只链接位置/关系复核记录，不复制完整台账。
